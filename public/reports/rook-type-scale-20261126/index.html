方法

  • 用带公司 SSO 的 headless Chrome 通过 CDP 打开生产页面，逐页点击到目标状态后截图。
  • 每页遍历 body *，跳过不可见元素，只统计含直接文本节点的元素，得到字号直方图。
  • 截图与统计各做一次：发布前（旧生产版本）18 页，发布后 19 页；发布后新增一个真实 Chat 会话。
  • 视口 1512×982、DPR 1；字号为计算值，单位为 CSS px。

剩余问题

  • 浏览器默认 <small>：34 处。父级 12px 时为 10px，父级 13px 时为 10.8333px。分布：ClawSec 管理页 27、设置·智能体 5、使用统计 1、反馈管理 1。这是目前唯一一类不在刻度上的 UI 字号。
  • Chat 消息内联代码：321 处。.markdown code { font-size: .9em } 按父级缩放：16px 正文里的代码为 14.4px（314 处）、12px 为 10.8px（4 处）、18px 为 16.2px（3 处）。这是内容样式，发布前已存在，不属于 UI 刻度。
  • 看板头像缩写 7px / 9px：设计保留的裸值。构建产物里只剩这 4 处裸 font-size。
建议（未实施）。加一行 small { font-size: var(--text-caption); } 可把 34 处拉回 11px。内联代码若要对齐绝对刻度，需要按父级字号分别取 token，会改变代码与正文的对比度，建议单独决定。

布局

  • 19 个页面均无溢出、无横向滚动、无换行破版；管理页表格列对齐，数字右对齐正常。
  • 看板卡片元信息从 10.5px 增至 11px，卡片略高，「未指派 · 更新于 X」仍单行容纳。
  • 模型配置页的推荐模型列表是固定高度滚动区，行高变大后约显示 4.5 行，第 5 行被容器边缘切断。滚动可用，视觉上像被裁，建议把高度改成整行数。
  • 使用统计新增「数据截至 …」一行，与统计卡片间距正常。
  • Chat 会话的 markdown 表格、引用、内联代码渲染正常；消息操作行、用量与 token 统计对齐全。
  • 设置弹窗四个 tab 的标签、说明、表单层级一致；智能体的 @名称 说明与运行身份行清晰。

结论

  • UI 主体的字号已全部落在 9 档刻度内，看板、管理页和设置页的越档清零。
  • 剩余不一致只有浏览器默认 <small>（34 处）与消息正文内联代码的相对字号（321 处）。
  • 布局在 1512×982 下稳定。唯一可见的密度问题是模型配置页推荐模型列表被容器裁掉半行。
