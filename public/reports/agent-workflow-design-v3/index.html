Kanban Bot 协作

智能体与 SuperAgent 设计方案 · 公开版 · 2026-11-27

结论

一个 Task 可以有多个 Bot。每个 Bot 负责独立工作，续用自己在这条 Task 上的系统内置 Session。Kanban 通过 SuperAgent 的 event inbox 交办，用户在原 Task 上看交付和审查结论。首个实现是验收人手动交办审查 Bot。

同一 Task 的分工

以「为导出增加日期筛选」为例。Task 持有目标、验收标准、交付版本和审查结论。开发 Bot 和审查 Bot 各自保存上下文，通过交付与结论交接。

参与方职责与上下文写回 Task
开发 Bot实现与返工。续用开发 Session，按授权使用工作环境。交付 v1、验证证据。负责人确认返工后，再提交 v2。
审查 Bot按验收标准审查指定版本。续用审查 Session，读取交办的材料。对 v1 提出缺少时区用例的结论。v2 提交后，针对 v2 给出复审结论。
Task 负责人和验收人负责人确认返工。验收人决定是否通过。Task 记录人工决定和相应交付版本。

Session 按 Task、Bot、当次参与定位。同一参与内的 Run 串行，不同 Bot 可以并行。新交付和人工确认可以触发下一轮。停止跟进后重新添加 Bot 会建立新 Session。Session 由系统管理，开发所需的工作环境单独授权。

事件与状态

Kanban 提交业务操作时一并持久化事件。事件包含来源、Task、目标 Bot、动作和交付版本。SuperAgent 的 worker 认领事件，核对参与状态和执行权限，再启动或续用 Session。每次执行有独立的事件和 Run 记录。

发生什么系统如何处理
接到交办按来源事件、Bot 和动作去重。等待 worker 认领。
认领后、Run 启动前发生重启worker 恢复持久化事件，复用同一个请求标识。超过恢复次数时记录失败。
Run 已启动后发生中断首版记录中断失败。验收人可针对当前交付重新交办。
Run 完成同一事务核对当前参与、权限和交付版本，写回结论并结算事件。
提交新版、撤销权限、停止跟进或关闭 Task写回重新检查当前条件。迟到的旧结果留在后台。

后续可以让故障 Webhook 与定时器投递同一类工作事件，再把结果送回各自来源。直接问答由 Chat 承接，采用对话自己的 Session。

逐步验收

步骤通过条件
创建与交办内置审查 Bot 启用后可交办。只有 Task 验收人可以针对待验收版本请求审查。
持久化事件Task 操作与事件一起提交。重复请求不产生额外 Run。重启后可处理待执行事件。
独立 Session连续交办续用该 Bot 的 Session。其他 Task、Bot 和后续参与各有独立 Session。审查 Run 只接收授权材料。
结果与停止结论绑定交付版本。新版或停止先提交时，旧 Run 无法写回。普通 Chat 无法打开后台 Session。
协作验收开发提交 v1，审查提出缺项，负责人确认返工，开发提交 v2，审查复审，验收人确认。每次执行独立可追溯。

当前源码接通单轮手动审查。本地集成测试覆盖投递、恢复、Session 隔离和写回。正式模型服务、生产环境和开发 Bot 联动仍待验收。
