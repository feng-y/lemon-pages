原则

  • Rook 驱动原生 Runtime，做法和 t3code、Orca 一样。压缩、skill、历史和子代理交给 Runtime 自己处理。
  • Rook 只写多用户这一层：Session 的用户隔离（执行 UID）、ClawSec 与用户 SSO 的绑定、Queue、定时任务、智能体的 owner 身份。
  • 参考代码：t3code（MIT，56dbca3bc5）、Orca（MIT，b9f7d01b3b4）、本机 dsh、t3code 生成的 Codex app-server 协议 schema。

冻结与恢复

规则

  • 有进行中的 Turn、待处理的审批、后台任务或 Queue 消息时，Session 不算空闲。这条沿用 Orca 的 idle stop。
  • 空闲 30 分钟冻结（IDLE_WORKER_FREEZE_MS）。ROOK_CHAT_MAX_IDLE_WORKERS 数量上限（默认 4）保留。
  • 每个 Turn 结束时 checkpoint 已经写进 MySQL，所以冻结不另写 checkpoint，只停进程，保留本地文件。

恢复：本地文件对比 MySQL head（revision、nativeSessionId、bytes、sha256）

本地文件处理
与 head 一致直接用本地文件，不读 MySQL 全文
缺失从 MySQL 拉到本地，再恢复
与 head 不一致以 MySQL 为准（MySQL 更新，或本地被改过）
含保存失败的 Turn该 Run 失败时删除本地文件，下一个 Turn 从 MySQL 恢复

随后原生恢复：Pi 打开 session 文件，Claude Code 用 resume，Codex 用 thread/resume。BOSS 上的旧 checkpoint 仍每次从 BOSS 读，下次保存时转进 MySQL。

各 Runtime 怎么冻结

  • 实测Pi：停掉 persistent worker。
  • 计划Claude Code：结束该 Session 的 query，然后停进程。
  • 推断Codex：发 thread/unsubscribe，等到 thread/closed。用户名下没有加载中的 thread 时，停掉该用户的 app-server。notLoaded 不代表已停，只有 idle 或 systemError 才算（Orca）。thread/closed 之前不发 thread/resume（t3code）。

中断的 Turn（已定：断开提示 + t3code 续跑规则）

  • 每个 interrupted 的 Turn 显示「Rook 服务重启，这一轮被中断」，并写明是否已自动续上。
  • 未开始工具：原样重发 prompt，每个 Run 最多 3 次（t3code MAX_RESENDS）。
  • 已开始工具：发续跑 Turn，要求模型先确认改状态的命令有没有生效再决定是否重复（t3code CONTINUE_PROMPT，MIT）。5 分钟内最多连续 3 轮。
  • 只留提示和「继续」按钮：Session 已删除或归档、用户按过 Stop、有待处理审批、SSO 验证失败。
  • 重发前重新验证执行用户的 SSO。Chat、智能体 Task、自动化任务共用这套规则，仍受 ROOK_UPGRADED_FLEET 控制。
  • Orca 没有证据时标 unverifiable。Rook 的 MySQL 租约过期就是证据，不需要这个状态。

Runtime 驱动

  • Pi：保持 persistent worker。
  • Claude Code：每个 Session 一个 Agent SDK query，streaming input 送后续消息，resume / resumeSessionAt 恢复。WIP 在 c724b6c，未验证。
  • Codex：每个用户一个 app-server，CODEX_HOME 放在用户目录，以执行 UID 运行，只 initialize 一次，出错整个淘汰。一个用户的多个 Session 是同一 app-server 上的多个 thread。
  • app-server 按用户划分，一个 app-server 里不会出现两个用户的 thread。

多智能体

Turn 内的子代理（Runtime 原生）

  • Codex：去掉 agents.enabled=false 和 features.multi_agent_v2=false。collabAgentToolCall 的 receiverThreadIds 记到父 Turn 下，Stop 能停到子 thread。
  • Claude Code：Task 工具的子代理事件归到父 Turn，作为折叠的 Step 展示。
  • Pi：没有原生子代理。按 dsh dsh-subagent 做 Pi extension，子代理是同一 worker 里的新 Pi session。排在最后。
  • 子代理不新增权限：执行 UID、ClawSec 身份和 Provider 都和父 Turn 一样。

Rook 智能体之间的协作

  • 阶段 0、1（目录、@名称、agent-inbox、Task 会话、owner 的 SSO）扩展到 Claude Code 和 Codex，Runtime 由智能体配置决定。
  • 委派：智能体在 Task 里 @ 另一个智能体，结果回到同一个 Task。参考 t3code delegated completion 和 dsh dsh-experimental-agent-team。
  • tools 白名单在执行边界生效（当前未生效）。

SSO、定时任务与续期

  • Web 请求先校验 SSO，Run 用执行用户的 SSO。智能体 Task 用 owner 的 SSO。自动化任务用创建者的 SSO，投递前重新验证。子代理继承父 Turn。这些都已实现，智能体只接通了 Pi。
  • 已有续期：SsoSessions.remember 在登录时保存 SSO。probeScheduledSessions 每小时验证定时任务创建者和已启用智能体的 owner，验证即保活，失败清除并发企业微信通知。
  • 计划智能体运行前先 authenticate(owner)，失败时 Task 标成「等待 owner 重新登录」。设置页显示每个智能体的 SSO 状态和最近验证时间。
