自动化 timer 审查与修复

关停、错过通知与投递延迟 · 2026 年 11 月 28 日

摘要

审查复现了关停与投递指标两处缺陷。修复后，timer 关停会结束企业微信脚本查找的等待，并取消正在运行的发送进程。投递延迟在定时执行直接受理为 Run 且回执保存后更新。

审查发现

场景复现结果修复
关停时正在查找脚本或发送通知查找阻塞时，发送仍在等待。发送进程原有的超时是 45 秒，长于 Backend 的 25 秒关停时限。timer 将取消信号传给查找等待和发送进程。
定时任务只拿到 Queue 回执延迟指标提前更新，此时尚无 Run。定时执行直接受理为 Run 且回执保存后，timer 更新延迟。兼容的 Queue 入队回执被排除。

通知中断后怎么恢复

timer 领取通知时保存 90 秒租约。发送中断后，另一 Backend 可以在租约到期时接管。已返回成功的发送照常保存结果。若企业微信已接收消息但成功结果未保存，接管时仍有重复通知的可能。

关停会结束发送对脚本查找的等待。共享的脚本查找可以继续完成，Backend 的数据库关停流程仍按原规则执行。

验证

定向测试覆盖阻塞的脚本查找、timer 取消发送、租约到期前后接管，以及只有 Queue 回执时延迟指标保持未更新。本地进程探测验证了取消后发送进程退出。

本地 MySQL 定向测试 66 项全部通过。默认全量测试通过 361 项，按环境条件跳过 163 项。静态检查和构建均通过。

合入状态

原改动与审查修复均已合入主分支。 线上滚动发布与企业微信实际送达留待部署验收。
