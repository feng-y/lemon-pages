智能体与 SuperAgent 设计方案

公开版 · 交互演示使用虚构示例

方案摘要

智能体是一位长期协作者，可以接收对话、工作来源和自动化。先从一个内置的 Kanban 协作者做起。验收人在 Task 中提及它，它对照评审标准检查交付证据，把缺项和建议写回原时间线。处理人补证后在 Task 留言，智能体接着处理，验收人负责通过或退回。

后续项目可将故障 Webhook 绑定给专门的智能体。SuperAgent 负责在事件之间保存状态并恢复工作。Chat 提供直接问答，每次发送推进一轮对话。

产品分工

智能体定义谁处理工作。SuperAgent 负责工作跨事件继续。Chat 承载直接对话。

概念职责例子
智能体有持续的身份、职责、运行环境、工作记录和访问权限。用户随时可以找到它，查看待处理事项和结果。内置「工作台助手」负责 Kanban 协作，项目配置「项目值班助手」处理故障。
BotOrca Bot、OpenBot 和 Grok Bot 所代表的长期协作者形态。对话、工作来源、定时任务和历史围绕同一位协作者组织。工作台沿用「智能体」名称，采用这一聚合方式。
SuperAgent保存工作进展，接收下一次唤醒，恢复对应会话并写回结果。收到恢复事件后结束本轮故障跟进。
Chat管理用户的对话和历史。用户可从智能体主页开始一条绑定该智能体的对话。问助手如何准备回滚演练，答案保存在这条对话里。

Orca 把待人处理、进行中的工作和对话放在 Bot 主页。此处参考的是 CopilotKit 的 OpenBot，它可组合不同的智能体、模型和运行环境。Grok Bot 让团队在已有渠道里找同一位协作者，也支持事件和定时唤醒。Multica 补充了工作区分工和权限的参考。

Task 状态 待验收

每次审查按当前 Task 提供的评审标准、执行证据和待验收交付说明判断。只有链接时标记为待核对。智能体可以通知处理人或验收人，验收人用 Kanban 完成通过或退回。首版验收使用 Task 内已有材料。后续读取代码审查和构建记录时，先核对仓库授权。

持续执行

同一个智能体可以通过多个入口工作。每项持续工作按来源保留独立会话、授权和结果去向。执行环境可在两次唤醒之间释放。首版通过每项工作的会话保留上下文，跨工作记忆后续按权限独立验收。

入口继续条件结果
Kanban提及后建立参与，后续 Task 评论串行推进。同一个 Task 上的多个评论可以合批。写回 Task 时间线。Task 完成或参与结束后停止跟进。
故障 Webhook来源绑定决定处理权限。同一故障轮次的事件续用会话，恢复事件结束本轮。故障处理记录与来源写回。新一轮故障创建独立会话。
自动化任务按已有计划向目标会话投递。持续工作需要定时复查时，由调度器产生唤醒事件。投递记录与目标会话。
Chat普通消息触发一轮。用户明确确认对象、唤醒条件和结果去向后，可在后续版本交办持续跟进。普通回复进入当前对话，持续工作的结果发往确认的目的地。

故障 Webhook 的处理规则

  1. 后端在确认收到前认证来源并持久化事件。来源绑定与事件标识共同去重。故障标识和发生轮次决定会话，来源有序版本决定是否接受状态更新。
  2. 后端串行推进同一轮故障。恢复后丢弃晚到的旧事件。只读诊断在执行边界强制限制项目和操作范围。
  3. 后端把诊断结果和送达状态分开保存。服务重启后继续处理待送达结果，重试前检查外部写回是否已成功。重试耗尽时保留待人工处理的记录。只有明确授权的目的地接收结果。
  4. 后端在派发和写回前复核权限。解绑、停用或权限撤销后停止进一步派发与写回。跨入口引用只传递当前用户可读取的摘要，历史、续问和分享继续校验来源权限。

实施与验收

顺序验收场景
Kanban 闭环真实运行身份完成提及、缺项审查、补证追评、通知和人工验收。验证同一会话续接和公开材料边界。
目录与直接对话验证独立入口、刷新、权限可见性和原有草稿恢复。验证首问、追问、切换智能体、停用与撤权。
单个故障来源先确定故障轮次与顺序、认证、诊断权限和写回目的地。验证重复与乱序事件、服务重启恢复、故障结束和跨故障隔离。
后续扩展按需验收跨入口引用、显式持续交办和下游交付。每种运行环境分别记录验收结果。
